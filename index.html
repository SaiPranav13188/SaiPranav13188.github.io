Architecture

Six agents, led by a coordinator, run as tool-calling loops. They classify the photo with Gemini vision, work out which office is responsible, draft a formal letter, submit it on the official portal with Playwright, then monitor the complaint and escalate it. Safety rules live inside the tools, and every tool call is logged for audit. It supports voice as well as text.

Decision

Hand OTPs back to the citizen. Never bypass them. The real municipal portal asks for a mobile OTP before the complaint form even appears. The agents check for CAPTCHAs and OTPs before filling a form and again after submitting it, and if one appears, the citizen gets a three-step hand-off. Monitoring and escalation still run automatically.

Trade-off

Filing isn't fully hands-off on gated portals, but the agents never automate their way around a human check. Behaviour against the real portal ↗

Architecture

A LangGraph pipeline over hybrid search (BM25 + dense + sparse, fused with RRF, in Qdrant), with a reranker, a corrective loop and a citation verifier. Answers stream to a phone-first Next.js PWA. Every part has an offline fallback, so it runs with no API key and on free hosting.

understand → decompose → retrieve → rerank
  → grade ⇄ rewrite / abstain
  → eligibility → ask → generate → verify

Decision

The AI never decides numbers. Eligibility rules live as JSON, and each rule quotes the exact sentence and page it comes from. Plain Python with three-valued logic decides eligible, not eligible or maybe.

On 11 profile questions the rule engine scored F1 100 against 74.8 for an LLM-only approach. The expected answers come from the same written rules, so the gap is the meaningful part, not the 100.

Smart questioning

The next question is the one with the highest expected information gain over the schemes still open. Across 30 synthetic profiles that took 11.77 questions to reach a decision, against 16.57 for a fixed questionnaire.

Results

  • With the full models: Recall@5 98.0, MRR 0.905, key-fact correctness 95.9, citations supported 99.4%.
  • Cross-lingual fusion (original query + English) was the biggest correctness win.
  • Load test at 50 concurrent users: 0 errors, chat p95 170 ms.
  • Official government documents back 13 of the 30 schemes so far, and one caught a wrong income limit in a summary.

Problem

LLM extraction invents plausible numbers. On an offer letter, a fake bond penalty could change someone's career decision, so "mostly right" isn't good enough.

Architecture

A LangGraph orchestrator routes each upload through privacy redaction, extraction, verification and moderation, with at most two retries and a token budget.

upload → privacy (redact ×3, re-scan)
       → extraction ⟲ self-check
       → verify_quote
       → verification → store | moderator

Decision

Every value needs a quote, or it gets dropped. verify_quote() checks that every quote exists in the redacted letter, and plain Python re-derives each value from its quote. The model never gets the last word on a number.

The cost: some true values get dropped and sent to the uploader to confirm. That trades recall for accuracy on purpose.

Results

  • Field accuracy rose from 88.5% (single pass) to 99.6% with the agentic self-check loop.
  • Hallucinated fields fell from 22 to 0.
  • 0 of 335 personal details leaked past redaction.

How it works

It draws a squarified treemap of any folder, gives each location a verdict with a one-line reason, and moves items to a holding area you can undo from.

Decision

Never delete anything. Move it to a holding area. If a cleanup tool gets it wrong even once, someone's files are gone for good. Moves are logged and can be undone for 30 days, and the rules for user data and system folders are checked first, so no later rule can mark anything inside them as safe.

The cost: space isn't freed until the holding period ends or you confirm. That's the point.

Privacy

Parsing happens on the phone. OTPs are never stored, and only the last four digits of accounts are kept. Budgets, subscriptions and split bills are all worked out from the parsed transactions.

Decision

Raw bank SMS never leaves the phone. Bank messages are some of the most sensitive data on a phone, and sending them to a server to parse is the easy route. The AI fallback is opt-in and masks text twice, on the phone and again on the server.

Trade-off

Every bank needs its own parser and test fixtures, instead of a single LLM call.

Background

How I work

I like the hard part of AI: making it reliable. I design multi-agent systems where the model plans and calls tools, but the safety rules live in code it can't talk its way around. Then I ship them as real products people can install.

01Guardrails in code, not prompts

Models choose what to do next. The rules about what they're allowed to do are enforced in the tools, so a model can't talk its way past them.

02Measure, then claim

Eval harnesses, pinned reference values and test suites come first, and I write down the known limits next to the results.

03Ship the whole thing

From the agent graph to the database, the mobile app, the deployment and the README, every project is something people can actually use.
